## Гипотеза

EXP-007 учитывает локальный мотив и GC-класс независимо. EXP-008 проверяет одно
следующее усложнение: одинаковый динуклеотид `[-1,0]` может иметь разный
добавочный эффект в разных GC-окружениях.

```text
score = k2 + k4 + k6 + GC-bin + interaction(k2, GC-bin)
```

Все main effects EXP-007 сохраняются без изменений. Добавляются только
reference-coded взаимодействия.

## Как кодируется interaction

Есть 17 категорий `k2`, включая `N/edge`, и 9 GC-bins, включая `missing`.
Чтобы interaction не дублировал уже существующие main effects, используются
reference levels:

- `TT` — reference для k2;
- `[0.35,0.40)` — reference для GC201-bin.

Поэтому добавляется `(17 − 1) × (9 − 1) = 128` столбцов, а не `17 × 9`.
Вместе с 4 379 признаками EXP-007 модель имеет 4 507 коэффициентов. Каждая
агрегированная строка активирует не более одного interaction-столбца.

## Сокращённый подбор C

Предыдущие эксперименты стабильно выбирали малую регуляризацию около
`C = 0.0003`. Поэтому заранее фиксируется локальная сетка:

```text
0.0001, 0.0002, 0.0003, 0.0005, 0.001
```

При трёх train-only folds это ровно **15 обучений**, а не 39. Validation не
используется ни для выбора `C`, ни для изменения сетки.

## Gate до validation

После выбора `C` кандидат сравнивается с EXP-007 на тех же трёх CV-fold.
Строгий confirmatory gate считается пройденным только если:

- все три candidate fits сошлись;
- AP выше EXP-007 на каждом из трёх folds;
- mean EPIC Spearman не ниже EXP-007.

После просмотра CV EXP-008 gate не прошёл из-за небольшого проигрыша на одном
fold. По явному решению эксперимент один раз доводится до validation в режиме
`exploratory_after_failed_cv_gate`, чтобы сохранить полный отрицательный или
пограничный результат. Этот run не может получить `adopt`: даже при сильном
validation возможен максимум `iterate`. Формальное решение `adopt` требовало бы
и пройденный train-CV gate, и прирост validation AP не меньше 1%, Spearman не
ниже EXP-007, и победу AP минимум на двух из трёх validation-contig.

## OpenMP warning

Первая setup-ячейка, до импорта NumPy/SciPy/sklearn, задаёт
`MKL_THREADING_LAYER=SEQUENTIAL` и ограничивает остальные OpenMP-пулы. Так в
процесс не загружается конфликтующая threaded-версия MKL. В fit также больше не
вызывается `threadpoolctl`, runtime-инспекция которого печатала предупреждение.
Solver, objective, regularization и коэффициенты модели от этого не меняются;
меняется только исполнение линейной алгебры. Перед началом EXP-008 нужен свежий
kernel, если в текущем уже запускался EXP-007.
