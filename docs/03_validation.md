## Локальное разбиение Nematostella: `contig_holdout_v1`

Учебный notebook: [[notebooks/01_train_validation_test.ipynb|Train, validation и test — код с пояснениями]]. Выполнен полностью 16.09.2026 в Miniforge `epic-eda`.
Исполняемый источник правил — `src/ml_project/epic_data.py`; experiment-notebooks
только вызывают его и поэтому не создают собственные несовместимые split.
Полный рабочий процесс: [[docs/epic_experiment_workflow.md]].

Из 12 официальных train-контигов выбираются 3 для validation: сортировка имён,
`numpy.random.default_rng(42).permutation`, первые `ceil(12 × 0.25)` имён.
Остальные 9 контигов используются для обучения. Официальные 3 test-контига
сохраняются целиком. Выбор не зависит от target; обе цепи, соседние позиции и
обе экспериментальные повторности одного контига относятся к одной части.

| Часть | Контигов | Position-strand | Доля всех разрешённых позиций |
|---|---:|---:|---:|
| Train | 9 | 228 064 160 | 59.317% |
| Validation | 3 | 83 807 486 | 21.797% |
| Test | 3 | 72 613 390 | 18.886% |

- Validation: `NC_064034.1`, `NC_064041.1`, `NC_064042.1`.
- Test: `NC_064037.1`, `NC_064044.1`, `NC_064046.1`.
- Все остальные контиги официального train назначены в локальный train.
- Положительных position-strand: train — 170 443, validation — 56 205.
  Нулевые позиции полностью сохранены через интервалы; sampling не выполнялся.

Выходная папка: `data/processed/jaNemVect1.1/splits/contig_holdout_v1/`.
`manifest.json` фиксирует назначения, seed, правило и SHA-256 исходных/выходных
файлов; рядом сохраняются таблицы интервалов, ненулевые ответы train/validation
и сводка. Повторный запуск проверяет совпадение существующих файлов до записи.

Notebook проверяет непересечение контигов, полное покрытие исходного train,
сохранение test-template, обе цепи и правильность адресации target. Позиции можно
получать небольшими порциями; одна гигантская таблица не создаётся. Test-labels
в этом notebook не читаются, test-target не заменяется нулями.

В следующих моделях fit и обучаемые преобразования выполняются только на train,
выбор признаков и параметров — по validation. После фиксации решений допускается
refit на train + validation перед итоговым test. ДНК-признаки и обучение модели
этот notebook пока не реализует.

Все официальные train-контиги уже участвовали в описательном EDA, поэтому новая
validation — рабочий holdout для разработки, а не ранее нетронутая выборка.
Разделение по контигам исключает пересечение координат и соседних окон, но само
по себе не исключает похожие последовательности на разных контигах.

Прежний [[notebooks/02_eda_logistic_context.ipynb|EDA model-probe]] использует
отдельный 3-fold CV. Его код и карточки экспериментов не переведены на новый
holdout; результаты разных схем нельзя сравнивать как полученные на одном split.
Шаблонные разделы ниже и автоматические блоки baseline заполняются на этапе
обучения и оценки моделей.

## Обязательные конкурсные метрики

| Метрика | Что измеряет | Implementation | Направление |
|---|---|---|---|
| **Average Precision (AP)** | Отделяет позиции с `target > 0` от нулевых по всему validation whitelist | `average_precision_score(target > 0, score)` | maximize |
| **EPIC Spearman** | Ранжирует величину сигнала среди положительных позиций | `pearsonr(dense_rank(target), dense_rank(score))` только при `target > 0` | maximize |

Обе метрики обязательны и отображаются отдельно для reference и candidate.
Критерий эксперимента должен заранее указать желаемое изменение одной метрики и
допустимый guardrail для второй. Точное определение находится в
[[docs/00_problem.md#Точное определение конкурсных метрик]].

Технические параметры CV и scorer для первого запуска задаются в
`src/ml_project/baseline_config.py`; обоснование этих параметров остаётся в этом
документе.

## Leakage checklist

- [ ] Один объект / пользователь не попадает в разные части вопреки production-сценарию.
- [ ] Все fit-операции выполняются только на train fold.
- [ ] Imputation, scaling, encoding и feature selection находятся внутри pipeline.
- [ ] Временные признаки используют только прошлое.
- [ ] Target encoding рассчитан out-of-fold.
- [ ] Дубликаты не пересекают split.
- [ ] Подбор threshold не использует holdout.
- [ ] Feature store / joins соблюдают point-in-time correctness.

## Политика честного сравнения

Во всех сравниваемых экспериментах фиксируются:

- версия датасета;
- split / folds;
- preprocessing boundary;
- основная метрика;
- seed или набор seeds;
- baseline;
- вычислительный бюджет.

Если изменилось несколько факторов одновременно, результат нельзя однозначно приписать одной гипотезе.
