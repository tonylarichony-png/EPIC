# 00 — Постановка задачи: EPIC 2026

← [[README.md|Dashboard]] · Далее → [[docs/01_data.md|Data]]

> [!abstract] Результат этапа
> Построить воспроизводимый метод, который по ДНК предсказывает положение и интенсивность начала транскрипции с точностью до нуклеотида и отдельно для двух цепей. Подготовить предсказания для пяти конкурсных видов EPIC.

## Кратко

- **Проблема:** найти закономерности, связывающие последовательность ДНК с сигналом начала транскрипции РНК-полимеразой II. Экспериментальный сигнал — число 5′-концов прочтений csRNA-seq.
- **Пользователь результата:** наша команда и исследователи; организаторы EPIC оценивают предсказания на скрытых экспериментальных ответах.
- **Как используется прогноз:** модель сканирует последовательности тестовых контигов, а оценки выбранных позиций поступают в систему оценки EPIC.
- **Ожидаемая ценность проекта:** проверить собственные гипотезы, получить измеримое улучшение относительно воспроизводимого baseline и сохранить метод, пригодный для сканирования новых последовательностей.
- **Почему здесь нужен ML:** полезные закономерности последовательности можно оценивать по экспериментальным примерам. Семейство модели заранее не закреплено: рассматриваем линейные модели, бустинг и CNN.

Биологическая постановка: [The data of EPIC](https://epic.autosome.org/docs/the-data-of-epic). Этот проект участвует в EPIC 2026; материалы IBIS используются только при явно указанной связи.

## Что и когда предсказывает модель (ML problem formulation)

| Вопрос | Ответ |
|---|---|
| Тип задачи | Предсказание профиля сигнала; оценка сочетает бинарную классификацию наличия сигнала и ранжирование его интенсивности |
| Для кого или чего делается один прогноз | Для одной позиции конкретной сборки генома и одной цепи ДНК |
| Что является одной строкой / наблюдением | (observation_unit:: сборка генома + контиг + координата нуклеотида + цепь) |
| Что предсказываем (target) | (target_definition:: число 5′-концов csRNA-seq в позиции и цепи после объединения двух экспериментальных повторностей) |
| Когда модель делает прогноз | После обучения, при сканировании ДНК отложенных или новых последовательностей |
| Какие данные доступны модели в момент прогноза | ДНК и производные от неё признаки; сборка, координаты и цепь для адресации; whitelist/template задают позиции выдачи результата |
| Горизонт прогноза | Не применимо: задача пространственная, по координатам генома |
| Какой результат возвращает модель | Один числовой score на позицию и цепь; преобразование внутренних предсказаний в формат EPIC фиксируется вместе с моделью |
| Как часто выполняется прогноз | Локально после выбранных экспериментов, затем полный проход для подготовки конкурсных файлов |

> [!warning] Leakage contract
> Экспериментальные csRNA-seq/sRNA-seq треки обучающих контигов используются при обучении и анализе; соответствующих треков тестовых контигов у модели нет. Локальную validation выделяем из официального train целыми контигами/хромосомами до обучения. Перекрывающиеся окна одной последовательности не должны попадать одновременно в обучение и проверку.

Конкретный список локальных контигов, правила отбора окон и настройки преобразования score предстоит зафиксировать в [[docs/03_validation.md]].

## Метрика и критерий успеха

| Вопрос                                      | Ответ                                                                                                                                                          |
| ------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Конкурсная метрика 1                        | **Average Precision (AP / AUPRC)** по всем оцениваемым позициям                                                                                                |
| Конкурсная метрика 2                        | **EPIC Spearman**: Pearson-корреляция плотных рангов target и score только на позициях с положительным target                                                   |
| Почему нужны обе                            | AP проверяет обнаружение ненулевого сигнала, EPIC Spearman — правильное ранжирование силы уже обнаруженного положительного сигнала                              |
| Вторичные диагностические метрики           | Время обучения и полного предсказания, RAM/VRAM, качество по контигам и видам, доля совпадающих scores после округления                                        |
| Минимально приемлемый результат             | Воспроизводимый baseline, корректный файл предсказаний и вычислимые обе конкурсные метрики на зафиксированной локальной validation                             |
| Желаемый результат                          | Подтверждённое улучшение относительно baseline с контролем обеих метрик и стоимости; численные пороги задать после первого измерения и до сравнения кандидатов |
| Как проводится финальная / внешняя проверка | Онлайн-лидерборд использует одну половину скрытых тестовых меток; итоговая оценка — другую                                                                     |

### Точное определение конкурсных метрик

- **AP / AUPRC:** `average_precision_score(y > 0, score)` по всем позициям оцениваемого набора, включая нулевые.
- **EPIC Spearman:** на подмножестве `y > 0` выполнить `rankdata(..., method="dense")` отдельно для target и score, затем `pearsonr` полученных рангов. Стандартный `spearmanr` с обработкой совпадений по умолчанию не эквивалентен этому определению.
- Итоговое место определяется агрегированием рангов по двум метрикам и видам через log-ranks. AP в поле шаблона не заменяет этот конкурсный критерий.

Источник: [Performance evaluation & metrics](https://epic.autosome.org/docs/performance-evaluation-metrics).

В локальном отчёте сохраняем обе метрики также после преобразования и округления scores до формата сабмита. Подбор преобразования проводим на выделенной части train. Для автоматических запусков ещё потребуется адаптировать scorer: исходный числовой target и бинарное событие `y > 0` имеют разные роли.

Подробный и неизменяемый протокол сравнения моделей фиксируется в [[docs/03_validation.md]].

## Границы проекта

- **Входит в проект:** проверка и подготовка конкурсных данных; EDA; признаки из ДНК; простые baseline; контролируемое сравнение семейств моделей; локальная validation; подготовка и проверка файлов EPIC; описание метода и воспроизводимый scanner для произвольного FASTA.
- **Не входит в проект:** сбор собственных внешних экспериментальных обучающих данных, перенос задачи на IBIS, клиническое применение и разработка постоянно работающего веб-сервиса.

### Выбор моделей

Начальная рабочая последовательность: простой baseline → линейные модели на признаках из ДНК → обоснованные усложнения, включая бустинг или небольшую CNN. Это план проверки, а не установленный победитель. sklearn-часть шаблона сохраняем; поддержку PyTorch добавляем при переходе к нейросетевому эксперименту. Батчи и обработка частями применимы к разным моделям при ограничениях памяти.

Предоставленные материалы Claude Science служат источником идей и кода для изучения. Числа из write-up не являются результатами нашего проекта. Прямой повтор готового решения без собственного изменения не отправляем в лидерборд, согласно просьбе, переданной вместе с материалами.

### Результат для соревнования

Для каждого конкурсного вида нужен отдельный `predictions.txt.gz`: одно число от 0 до 1 на строку, до пяти знаков после запятой, без заголовка и координат. Порядок задаёт `template.test.bed.gz`: сначала все позиции `+`, затем `-`; внутри интервала координаты возрастают для обеих цепей. Один score используется при оценке обеих метрик. Перед загрузкой выполняем официальный validator. [Формат EPIC](https://epic.autosome.org/docs/epic-submission-format).

| Вычислительные ресурсы и стоимость | Локально около 32 GiB RAM и AMD Radeon RX 6750 GRE 12GB; работоспособность выбранной связки PyTorch/ROCm ещё не проверена. CPU-baseline доступен как начальное направление |
| Интерпретируемость | Сохранять описание признаков/архитектуры, проверяемую гипотезу и разбор результата; биологический смысл признака остаётся гипотезой до проверки |
| Privacy, лицензии и правила использования данных | Соблюдать ограничения на внешние данные и распространение конкурсных данных, перечисленные ниже и в [[docs/01_data.md]] |
| Доступная инфраструктура | Windows, Python-ноутбуки и модули, Obsidian; репозиторий [tonylarichony-png/EPIC](https://github.com/tonylarichony-png/EPIC), ветка `main` |
| Срок / контрольная точка | Старт конкурса — 04.09.2026, объявленный основной дедлайн — 30.11.2026; ближайшая рабочая точка — загрузчик и зафиксированная локальная validation |

Даты проверены 15.09.2026: [Challenge timeline](https://epic.autosome.org/docs/challenge-timeline). Точное время закрытия и возможные изменения проверяем перед финальной отправкой.

### Правила участия

- Новое обучение и дообучение — на предоставленных конкурсных данных. Внешние данные, включая сторонние аннотации генов, запрещены; для существующих предобученных моделей предусмотрено исключение.
- Согласно уточнению организаторов от 10.09.2026, переданному владельцем проекта, допустимая исходная предобученная модель должна существовать до старта конкурса. Фиксируем её версию и дату checkpoint.
- Описываем метод и использование LLM/агентов. Для призёров требуется воспроизводимый протокол и инструмент сканирования последовательностей.
- Лимит — 10 файлов в день на команду, каждый вид считается отдельно. Финальным считается последний отправленный файл по виду до закрытия лидерборда.

Основной источник: [General rules](https://epic.autosome.org/docs/general-rules). Уточнения из сообщения организаторов храним как отдельный источник требований, а не как проверенный текст сайта.
