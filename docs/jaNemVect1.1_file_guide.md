# jaNemVect1.1 — понятный справочник по папкам и файлам

← [[docs/01_data.md|Паспорт исходных данных]] · [[README.md|Dashboard]]

> [!abstract] Главное в одном абзаце
> `genome/` содержит буквы ДНК, из которых строятся признаки модели.  
> `for_participants/` содержит разрешённые координаты, порядок строк и обучающие csRNA-ответы.  
> `ground_truth/` содержит опубликованные ответы демонстрационного test и не должен участвовать в обучении.  
> `scoring/` делит test на публичную и финальную части для расчёта метрик.

## Общая логика датасета

```text
genome.fa.gz
    │
    │ ДНК-последовательность нужного contig
    ▼
template / whitelist ──► contig + coordinate + strand
    │                              │
    │                              ▼
    │                     окно ДНК вокруг позиции
    │                              │
    ▼                              ▼
csRNA train ───────────► обучающий объект X → target y

X = признаки, полученные из ДНК
y = csRNA-сигнал или индикатор csRNA > 0
```

Модель должна научиться связи:

```text
последовательность ДНК вокруг позиции → вероятность/сила csRNA-сигнала
```

## Четыре понятия, которые встречаются во всех файлах

### Contig

Отдельный непрерывно собранный фрагмент генома, например `NC_064034.1`.
Одинаковая координата на разных contig обозначает разные места.

### Coordinate

Номер нуклеотида внутри contig. BED использует нумерацию с нуля.

```text
Последовательность:  c a c c c t ...
Координата BED:      0 1 2 3 4 5 ...
```

### Strand

Цепь ДНК: `+` или `-`. Для `-` последовательность разворачивается и заменяется
на комплементарную, чтобы upstream/downstream имели одинаковый смысл для модели.

### BED-интервал

BED хранит интервал как `[start, end)`: `start` включён, `end` не включён.

```text
NC_064034.1    1943    3761
```

Это позиции `1943…3760`, всего `3761 - 1943 = 1818` нуклеотидов.

## 1. Папка `genome/`

### `genome/genome.fa.gz`

Сжатый FASTA с последовательностями всех contig сборки.

Реальный фрагмент:

```fasta
>NC_064034.1
caccctacccctaccctaaccctaaccctacaccctaaccctaaccctca
accctaaccctaccctaccctaaccctaaccctaaccctaccctaaccct
```

- строка с `>` — идентификатор contig;
- следующие строки — нуклеотиды `A/C/G/T`, иногда `N`;
- явной нумерации нет: координата определяется положением символа;
- переносы строк не являются разрывами последовательности.

Это главный источник признаков модели. По координате из template программа
вырезает, например, окно `[-50, +50]` и кодирует его для модели.

### `genome/genome.fa.fai`

Индекс FASTA. Пример:

```text
NC_064034.1    22168631    13    50    51
```

Основные поля:

1. `NC_064034.1` — contig;
2. `22168631` — длина contig;
3. `13` — байтовое смещение начала последовательности в FASTA;
4. `50` — нуклеотидов в строке;
5. `51` — байтов в строке вместе с переводом строки.

Индекс позволяет быстро извлекать участок FASTA, не читая весь геном от начала.
Сам по себе признаком модели не является.

### `genome/assembly_report.txt`

Паспорт сборки генома: идентификаторы последовательностей, роли contig/scaffold,
длины и соответствия accession. Нужен для проверки происхождения и согласования
названий. В матрицу признаков не передаётся.

## 2. Папка `for_participants/`

Это основная рабочая папка участника: train-сигналы, разрешённые области и
шаблоны порядка train/test.

### `whitelist.train.bed.gz`

Список областей, на которых разрешено формировать обучающие примеры.

```text
NC_064034.1    1943    3761
NC_064034.1    3806    4561
```

Whitelist не содержит ДНК, strand или target. Он отвечает только на вопрос:
«Какие координаты входят в задачу?»

Критически важное правило:

```text
позиция внутри train-whitelist, csRNA-строки нет → count = 0
позиция вне train-whitelist, csRNA-строки нет   → позицию не используем
```

Обычные whitelist-файлы описывают repeat-free области. Промежутки между
интервалами исключены из официального множества обучения/оценки.

### `whitelist.test.bed.gz`

То же самое для test: области, для которых нужно сформировать прогноз.
Правильных ответов участнику этот файл не сообщает.

Train- и test-whitelist находятся на разных contig. Это важно для честной
валидации: близкие окна одного contig нельзя случайно распределять между train и
validation как независимые строки.

### `template.train.bed.gz`

Упорядоченная карта train-интервалов с цепью:

```text
NC_064034.1    1943    3761    .    0.0    +
NC_064034.1    3806    4561    .    0.0    +
```

Шесть BED-полей:

```text
contig  start  end  name  score  strand
```

- `.` — служебное пустое имя;
- `0.0` — заполнитель BED score, а не csRNA-target;
- `+`/`-` — цепь.

Сначала в template идут все интервалы `+`, затем те же интервалы `-`. Одна
BED-строка разворачивается во все нуклеотиды интервала. Например,
`1943–3761` соответствует 1818 отдельным position-strand.

Template связывает строку плотного TXT с `(contig, coordinate, strand)`.

### `template.test.bed.gz`

Упорядоченная карта test-позиций, для которых модель должна выдать prediction.
Итоговый файл должен иметь одно число для каждой развёрнутой position-strand
строго в этом порядке: сначала `+`, затем `-`; координаты внутри интервала идут
по возрастанию даже для `-`.

### `template.test.txt.gz`

Готовый пример файла submission с одним случайным числом от 0 до 1 на строку:

```text
0.76523
0.34256
0.67400
```

Это не предсказания организаторов и не test-ответы. Файл показывает нужный
формат, длину и точность записи. Реальная модель должна заменить эти числа своими.

### `csRNA-r1-train.bed.gz`

Разреженный csRNA-сигнал первой экспериментальной повторности.

```text
NC_064034.1  51582  51583  NC_064034.1:51582,-^44  44  -
```

Это означает: в позиции `51582` на цепи `-` первая повторность обнаружила
44 csRNA-прочтения. В BED записаны только ненулевые сигналы.

Файл уже отфильтрован по repeat-free train-областям и согласован с whitelist.
Он нужен для анализа повторности и формирования target, но count нельзя давать
модели как входной признак.

### `csRNA-r2-train.bed.gz`

Тот же формат для второй экспериментальной повторности. Повторности нужны, чтобы
оценивать воспроизводимость сигнала и уменьшать влияние случайного лабораторного
шума.

### `csRNA-r1-train-unfiltered.bed.gz`

Первая csRNA-повторность до фильтрации геномных повторов. Содержит ненулевые
позиции на train-contig, включая области вне repeat-free whitelist.

Для официальной model-ready выборки используется фильтрованный файл без
`-unfiltered`. Unfiltered полезен для контроля потерь при фильтрации и отдельных
исследований, но нельзя смешивать его позиции с whitelist-отрицательными.

### `csRNA-r2-train-unfiltered.bed.gz`

Неотфильтрованный аналог второй csRNA-повторности. Назначение такое же, как у
`csRNA-r1-train-unfiltered.bed.gz`.

### `csRNA-r1-train.txt.gz`

Плотное представление первой csRNA-повторности. В отличие от BED, содержит и
нули: одно значение на каждую развёрнутую строку `template.train`.

```text
0
0
4
0
...
```

Порядок нельзя менять. Первая строка относится к первой position-strand из
template, вторая — ко второй и так далее.

### `csRNA-r2-train.txt.gz`

Плотное представление второй повторности в том же порядке.

### `csRNA-train.txt.gz`

Основной объединённый обучающий target:

```text
pooled_csRNA = csRNA_r1 + csRNA_r2
```

Пример:

| Позиция | r1 | r2 | pooled |
|---|---:|---:|---:|
| A | 44 | 31 | 75 |
| B | 0 | 3 | 3 |
| C | 0 | 0 | 0 |

Для текущей бинарной постановки:

```text
y = 1, если pooled_csRNA > 0
y = 0, если pooled_csRNA = 0
```

Исходный count можно сохранять для анализа интенсивности и регрессионной
метрики, но он не входит в `X`.

### `rnaseq-r1-train.bed.gz`

Разреженный контрольный RNA/sRNA-сигнал первой повторности:

```text
NC_064034.1  51582  51583  NC_064034.1:51582,-^4  4  -
```

Он помогает понять, насколько csRNA специфичен, а насколько совпадает с общей
RNA-активностью или техническим фоном. Это вспомогательный контроль, а не основной
target задачи.

На настоящем test этот сигнал участнику недоступен, поэтому его нельзя включать
в признаки основной модели. Допустимые применения: EDA, контроль качества,
анализ специфичности и отдельно обоснованное auxiliary/multitask-обучение.

### `rnaseq-r2-train.bed.gz`

Контрольный RNA/sRNA-сигнал второй повторности. Используется аналогично r1.

### `rnaseq-r1-train-unfiltered.bed.gz`

Первая контрольная RNA-повторность до repeat-фильтрации. Включает позиции вне
официального repeat-free whitelist.

### `rnaseq-r2-train-unfiltered.bed.gz`

Вторая контрольная RNA-повторность до repeat-фильтрации.

### `rnaseq-r1-train.txt.gz`

Плотный RNA-контроль r1: одно значение на каждую position-strand в порядке
`template.train`, включая нули.

### `rnaseq-r2-train.txt.gz`

Плотный RNA-контроль r2 в том же порядке.

### `rnaseq-train.txt.gz`

Объединённый контрольный сигнал:

```text
pooled_rnaseq = rnaseq_r1 + rnaseq_r2
```

Он нужен для анализа, но не заменяет `csRNA-train.txt.gz` и не определяет
положительный класс основной задачи.

## 3. Папка `ground_truth/`

Эта папка открыта только у демонстрационной Nematostella. Для конкурсных видов
аналогичные ответы скрыты от участников.

### `ground_truth/csRNA-test.txt.gz`

Настоящий pooled csRNA-target для test. Значения расположены в том же порядке,
что и позиции `template.test.bed.gz`.

Использовать только как финальный отложенный ответ для проверки scorer. Нельзя:

- обучать на нём модель;
- подбирать признаки или параметры по нему;
- включать его значения в `X`;
- многократно смотреть на него как на обычную validation.

Иначе demo-test перестанет быть честной независимой проверкой.

### `ground_truth/rnaseq-test.txt.gz`

Настоящий pooled контрольный RNA/sRNA-сигнал для test. В основную официальную
оценку csRNA не входит; может применяться в post-challenge анализе. Для модели,
которая должна работать только по ДНК, этот файл недоступен при inference.

Оба test-TXT содержат по 72 613 390 значений для Nematostella.

## 4. Папка `scoring/`

Нужна не для обучения, а для воспроизведения конкурсной оценки.

### `scoring/half1-test.bed.gz`

Интервалы первой случайной половины test. Эта половина использовалась для
публичного online leaderboard.

### `scoring/half2-test.bed.gz`

Интервалы второй половины test. Эта половина предназначалась для финальной
оценки, чтобы участники не могли переобучиться на публичный leaderboard.

### `scoring/mask1-test.txt.gz`

Плотная маска первой половины в порядке `template.test`:

```text
1  → учитывать prediction/target при расчёте метрики
0  → игнорировать
```

### `scoring/mask2-test.txt.gz`

Маска второй половины. Логика та же; она выбирает другую часть test.

Scorer отдельно считает метрики для двух половин и при необходимости для полного
test. Эти маски не являются признаками и не должны влиять на обучение модели.

## Sparse BED и dense TXT — короткое сравнение

| Представление | Что хранит | Нули | Координаты | Типичное применение |
|---|---|---:|---:|---|
| `*-train.bed.gz` | Только ненулевые сигналы | Нет | Да | Аудит, анализ позиций |
| `*-train-unfiltered.bed.gz` | Ненулевые сигналы до repeat-фильтра | Нет | Да | Контроль фильтрации |
| `*-train.txt.gz` | Значение для каждой template-position | Да | Нет | Плотный target в фиксированном порядке |

Важная деталь: BED-строка может иметь длину больше одного нуклеотида. Нужно
раскрывать все координаты `range(start, end)`, а не считать строку одной позицией.

## Что использовать в нашей модели

| Роль | Файлы | Как используем |
|---|---|---|
| Признаки `X` | `genome.fa.gz` | ДНК-окна, reverse complement для `-`, sequence-признаки |
| Координаты train | `whitelist.train`, `template.train` | Определение допустимых position-strand и порядка |
| Target `y` | `csRNA-train.txt.gz` или сумма r1/r2 BED | Count и/или `int(count > 0)` |
| Анализ повторностей | `csRNA-r1`, `csRNA-r2` | Согласованность и шум, не вход в `X` |
| Контрольный анализ | `rnaseq-*` | EDA/QC, не вход в основную `X` |
| Координаты inference | `whitelist.test`, `template.test` | Где и в каком порядке выдавать prediction |
| Финальная demo-проверка | `ground_truth`, `scoring` | Только после фиксации модели |

## Главные ошибки, которых нужно избегать

1. Не использовать координату или contig как числовой биологический признак.
2. Не считать отсутствие sparse BED-строки нулём вне whitelist.
3. Не забывать раскрывать многонуклеотидные BED-интервалы.
4. Не менять порядок плотных TXT относительно template.
5. Для `-` брать reverse complement ДНК-контекста.
6. Не включать csRNA/rnaseq counts в `X`, если при inference их нет.
7. Не обучаться и не подбирать модель по `ground_truth`.
8. Не склеивать контекст через границу соседних contig.

## Минимальный путь одного обучающего объекта

```text
1. template.train даёт:
   NC_064034.1, coordinate=51582, strand=-

2. whitelist.train подтверждает:
   позиция разрешена для обучения

3. genome.fa.gz даёт:
   окно ДНК вокруг 51582

4. strand=- требует:
   reverse complement окна

5. csRNA r1/r2 дают:
   pooled count = r1 + r2

6. получаем:
   X = признаки последовательности
   y_count = pooled count
   y_binary = int(pooled count > 0)
```
