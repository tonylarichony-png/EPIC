## Словарь данных: что означает каждая колонка

### Что такое одна строка

Одна строка соответствует **одной позиции конкретного контига и одной цепи ДНК**:

```text
(assembly, contig, coordinate_0based, strand)
```

Например, позиции `NC_064034.1 : 1050 : +` и `NC_064034.1 : 1050 : -` имеют одинаковую физическую координату, но являются двумя разными наблюдениями: транскрипция на двух цепях имеет разное направление и отдельный target.

### Колонки model-probe таблицы `sample_rows.csv.gz`

| Колонка | Тип / пример | Что означает | Использование |
|---|---|---|---|
| `row_id` | integer, `0` | Последовательный номер строки внутри созданной pilot-выборки. Не имеет биологического смысла. | Только проверка порядка и join; **не признак** |
| `template_index` | integer, например `1589021` | Позиция строки в полном плотном train-template EPIC. Это служебный индекс, а не координата внутри контига. | Сопоставление с template и OOF; **не признак** |
| `contig` | string, `NC_064034.1` | Имя отдельной непрерывно собранной последовательности в FASTA. Контиг похож на длинный фрагмент генома; он не обязательно равен полной хромосоме. Контекст нельзя продолжать через его границу. | Извлечение FASTA и grouped split; **не признак** |
| `coordinate_0based` | integer, `1050` | Координата нуклеотида внутри contig, начиная с нуля. Значение `1050` соответствует 1051-й букве FASTA. | Извлечение окна из FASTA; **не признак** |
| `strand` | `+` или `-` | Цепь ДНК, для которой предсказывается сигнал. `+` читается в ориентации FASTA; для `-` контекст reverse-complement, чтобы upstream/downstream имели единый смысл. | Ориентация последовательности; **не самостоятельный признак** |
| `fold` | `0`, `1` или `2` | Номер локальной validation-группы. Все строки одного contig и обе его цепи получают один fold. | Разделение train/validation; **не признак** |
| `count` | non-negative integer, `0`, `1`, `17` | Суммарное число 5′-концов csRNA-seq в позиции: `r1_count + r2_count`. | Диагностика интенсивности и dense-rank correlation; **не признак бинарной модели** |
| `target` | `0` или `1` | Цель логрегрессии: `1`, если `count > 0`; иначе `0`. | Вектор ответов `y` |
| `population_weight` | positive float | Сколько исходных position-strand данного `contig × class` представляет выбранная строка. Нужен из-за отбора 1500 positive и 6000 negative на контиг. | Вес evaluation; **не признак** |

Колонка `assembly` не дублируется в каждой строке pilot CSV, потому что весь файл относится к одной фиксированной сборке `jaNemVect1.1`. Она записана в `provenance.json`.

### Термины, которые легко перепутать

- **Contig** — отдельная последовательность FASTA. Координата имеет смысл только вместе с именем contig.
- **Position / coordinate** — номер буквы внутри contig. В коде и BED используется система **0-based**.
- **Strand** — направление цепи. Одинаковые contig и coordinate на `+` и `-` — разные объекты.
- **Whitelist** — интервалы, внутри которых разрешено обучение или оценка. Позиция вне whitelist не превращается в отрицательный пример.
- **Template** — фиксированный порядок всех разрешённых position-strand для плотного target или prediction. В Nematostella сначала идёт блок `+`, затем блок `-`.
- **`N` в FASTA** — неизвестный нуклеотид, а не пропущенный target. Он кодируется отдельной категорией.
- **Край contig** — контекста за границей последовательности физически нет. Для агрегатов это отдельный `edge_fraction`; окна никогда не переходят в следующий contig.

### Исходные BED6-колонки

Разреженные csRNA-файлы организаторов имеют шесть полей:

| № | BED-поле | Значение |
|---:|---|---|
| 1 | `chrom` / contig | Имя последовательности, например `NC_064034.1` |
| 2 | `start` | Начало интервала, 0-based, включительно |
| 3 | `end` | Конец интервала, исключительно: интервал `[start, end)` |
| 4 | `name` | Служебный идентификатор записи; в признаки не входит |
| 5 | `score` | Положительный integer count данной повторности |
| 6 | `strand` | `+` или `-` |

Одна BED-строка может покрывать несколько нуклеотидов. Reader раскрывает `[start, end)` до отдельных position-strand и присваивает каждой покрытой позиции указанный count. После этого две csRNA-повторности объединяются:

```text
count = csRNA_r1_count + csRNA_r2_count
target = int(count > 0)
```

Отсутствие ключа в разреженном csRNA BED означает `count=0` только если позиция находится внутри train-whitelist. Экспериментальные counts, `row_id`, `template_index`, координата, contig и strand в матрицу признаков `X` не передаются; `X` строится только из последовательности FASTA.

### Важно: batch, sample и fold — разные вещи

> [!warning] Не делить строки случайно
> Соседние позиции имеют почти одинаковые перекрывающиеся окна ДНК. Если случайно распределить отдельные строки между train и validation, модель увидит в train почти тот же контекст, который затем оценивается в validation. Это leakage и завышенная метрика.

| Понятие | Для чего используется | Правило в этом EDA |
|---|---|---|
| **Fold / validation split** | Честная оценка обобщения | Единица разделения — целый `contig`; обе цепи и все координаты contig находятся только в одном fold |
| **Sample** | Сократить 311.9 млн строк до доступного model-probe | Внутри каждого contig без замещения выбираются 1500 positive и 6000 negative; `population_weight` восстанавливает численность страт при evaluation |
| **Compute chunk / batch** | Ограничить RAM при чтении FASTA и полном inference | Это только техническая порция строк; она не определяет train/validation и не должна менять fold |

Для текущего `sklearn.LogisticRegression(solver="lbfgs")` mini-batch обучения нет: каждый fit получает всю обучающую часть двух folds сразу. Чанки нужны при подготовке признаков и будущем полном сканировании, но не для обновления коэффициентов текущей модели.

Метаданные нужны именно для контроля этого процесса:

- `contig` задаёт статистическую группу и запрещает утечку между folds;
- `coordinate_0based + strand` однозначно определяют наблюдение и окно FASTA;
- `fold` сохраняет воспроизводимое назначение группы;
- `template_index` позволяет вернуть prediction в правильный порядок EPIC;
- `population_weight` корректирует искусственную долю классов в pilot-выборке;
- `row_id` обеспечивает безопасный join таблиц и OOF-предсказаний.

Даже split по contig не исключает одинаковые или гомологичные последовательности на разных контигах. Поэтому отдельно проверяются точные совпадения 101-bp окон; для подтверждающей оценки потребуется также оценить дальние гомологичные повторы.

- **Интерпретация дисбаланса:** accuracy непригодна как основной ориентир. В будущей оценке сохраняем все позиции выбранного whitelist, включая нули. При исследовательском oversampling/undersampling явно указываем исходные доли и схему отбора.
- **Изменение во времени:** временной оси наблюдений нет; изменения протокола эксперимента по времени не исследованы.
- **Различия по ключевым сегментам:** частота target измерена по 12 train-контигам, цепям, регистру и центральному N; контиги отличаются, поэтому разделяются целиком.
- **Label noise и неопределённые случаи:** Jaccard повторностей 0.21418; Pearson `log1p` counts на общих положительных 0.83106. Несовпадение повторностей само по себе не задаёт математический потолок качества модели.
- **Неожиданные закономерности:** слабый видимый сигнал или нулевой readcount не доказывает биологическую невозможность транскрипции. Утверждения о связи `N`, регистра и target из чужого write-up требуют собственной проверки.
- **Следствие для будущих линейных моделей:** логистическая регрессия учится событию `target > 0`; обычная регрессия использует величину target или её преобразование. Выбор фиксируем после анализа положительных отсчётов, учитывая обе конкурсные метрики.

### Вопросы о пропусках

- **Обычные NaN:** готовой таблицы признаков пока нет; доли NaN для будущих признаков не рассчитаны.
- **`N` в ДНК:** неизвестный нуклеотид, требующий отдельного учёта. Посчитать доли на train/test whitelist и связь с train-target; не заполнять автоматически наиболее частой буквой.
- **Ноль в размеченном train:** отсутствие наблюдаемого сигнала в доступном эксперименте. Это отдельный случай от отсутствующей разметки.
- **Отсутствующие test-ответы:** у конкурсных видов скрыты намеренно; не заменять их нулями. У demo они доступны, но пока не загружены.
- **Границы последовательности:** контекст за пределами контига отсутствует. Будущие окна должны явно кодировать эту границу и не переходить в соседний контиг.
- **Проверка обработки:** на фиксированных validation-контигах сравнить согласованные варианты; статистики обработки вычислять на fit-части.

### Интерпретация ключей и дубликатов

- **Primary key:** `(assembly, contig, position, strand)` для pooled сигнала; при совместном хранении повторностей добавить `replicate` и тип трека.
- **Ожидаемая уникальность:** одна оценка на позицию и цепь внутри template конкретного набора.
- **Фактические дубликаты ключей:** пересечения whitelist и повтор position-strand внутри каждой реплики не обнаружены; dense TXT полностью совпали с развёрнутыми BED. Совпадающие окна последовательности между координатами проверены только выборочно.
- **Причина допустимых повторов:** одна координата на разных цепях, в разных повторностях или треках — разные наблюдения. Одинаковые окна ДНК на разных координатах могут быть биологическими повторами, а не ошибкой файла.

## Время

- **Тренды и сезонность:** не применимо к индексам геномных позиций; координата не является временем.
- **Структурные сдвиги:** исследовать различия между контигами, видами и тканями. Для первого анализа используется одна сборка актинии со смешанными стадиями.
- **Изменения процесса сбора:** история лабораторного протокола и партий в текущем паспорте не установлена; отсутствие временного поля не доказывает отсутствие batch effects.
- **Запаздывание label:** прогноз временного события не ставится; target — уже измеренный экспериментальный сигнал.
- **Подходящая временная граница holdout:** временной split не выбран; основные кандидаты на разделение — целые контиги/хромосомы.

## Группы и зависимости

- Миллионы позиций принадлежат одним и тем же контигам; соседние окна перекрываются. Число позиций не равно числу независимых наблюдений.
- Обе цепи, повторности и все перекрывающиеся окна одного удерживаемого контига должны оставаться в одной части разбиения.
- Для Nematostella официальный train-whitelist содержит только 12 контигов. Число групп и их неодинаковый размер нужно учитывать при выборе локальной validation.
- Вид, ткань/стадия и экспериментальная повторность — возможные источники различий. Близость среднего GC train/test не исключает сдвиги по другим признакам.
- Бутстрэп отдельных соседних позиций может недооценивать неопределённость. Для будущих интервалов качества рассмотреть контиги или достаточно длинные блоки с явным описанием схемы.

Выводы должны попасть в [[docs/03_validation.md]].

## Пропуски, выбросы и аномалии

<!-- auto:eda-anomalies:start -->

> По доле нулей в train Nematostella следуют `Q1 = median = Q3 = 0`, поэтому IQR равен нулю; MAD также равен нулю. Обычное правило верхнего IQR-порога пометит любой положительный target как выброс. Для этой задачи это не основание удалять положительные позиции. Отдельно исследуем распределение `target > 0` и согласованность экстремумов между повторностями.

| Проблема | Масштаб | Связь с target | Объяснение | Обработка |
|---|---:|---|---|---|

## Bias, покрытие и репрезентативность

- **Покрытие:** оцениваемый whitelist представляет отобранные участки генома; выводы не автоматически распространяются на исключённые повторы, короткие контиги и иные ткани.
- **Train/test GC:** у Nematostella 40.3286% против 40.2485%, разница −0.0801 процентного пункта. Это близость одного агрегата; полное отсутствие distribution shift не подтверждено.
- **Редкие события:** небольшая случайная выборка может содержать слишком мало положительных позиций для изучения закономерностей. Для исследовательских графиков указывать размер и способ отбора обеих групп.
- **Зависимость наблюдений:** позиции и цепи связаны общей последовательностью; оценки неопределённости должны учитывать группы.
- **Процесс измерения:** нулевые отсчёты могут отражать чувствительность эксперимента; сравнение повторностей ещё не проведено.
- **Обобщение:** закономерность на демонстрационной актинии не считается автоматически подтверждённой для пяти конкурсных видов.

import json
from pathlib import Path

assemblies = json.loads(Path("data/raw/genome_metrics.json").read_text())["assemblies"]
for name, a in assemblies.items():
    n = a["template"]["train"]["length"]
    p = a["whitelist"]["nonzeros"]["train"]
    for split in ("train", "test"):
        assert a["template"][split]["length"] == 2 * a["whitelist"][split]["size_bp"]
    print(name, {
        "positions": n, "positive": p, "zero": n - p,
        "positive_pct": 100 * p / n,
        "constant_ap": p / n,
        "gc_train_pct": 100 * a["whitelist"]["train"]["gc_fraction"],
        "gc_test_pct": 100 * a["whitelist"]["test"]["gc_fraction"],
