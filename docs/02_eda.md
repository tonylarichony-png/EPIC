## Вопросы исследования

1. Насколько редок ненулевой csRNA-сигнал и как распределены положительные readcounts? **Доля положительных установлена по JSON; распределение величин ещё не исследовано.**
2. Насколько согласуются две csRNA-повторности по наличию и величине сигнала? Какую часть положительных позиций видит каждая повторность?
3. Чем отличаются контиги, цепи, участки со строчными буквами и `N`? Сохраняются ли связи с target внутри отдельных контигов?
4. Связаны ли GC-состав, локальный контекст и короткие мотивы с наличием сигнала и его величиной? Нужны ли позиционные признаки и взаимодействия?
5. Совпадают ли FASTA, BED и TXT по координатам, длинам и порядку цепей? Как представлены интервальные записи, нули и отсутствие разметки?
6. Какие зависимости требуют разделения train/validation целыми контигами? Какие доступные файлы нельзя использовать как признаки при inference?
7. Как исследовать и затем обучать линейный baseline в пределах памяти, сохранив естественное распределение данных при оценке?
8. Какие условия будущего сравнения с CNN нужно зафиксировать: данные, split, обе метрики, преобразование score и вычислительный бюджет?

- **Интерпретация дисбаланса:** accuracy непригодна как основной ориентир. В будущей оценке сохраняем все позиции выбранного whitelist, включая нули. При исследовательском oversampling/undersampling явно указываем исходные доли и схему отбора.

- **Label noise и неопределённые случаи:** разногласия повторностей могут отражать экспериментальную вариативность и низкое покрытие. Их величина пока неизвестна; несовпадение повторностей само по себе не задаёт математический потолок качества модели.
- **Неожиданные закономерности:** слабый видимый сигнал или нулевой readcount не доказывает биологическую невозможность транскрипции. Утверждения о связи `N`, регистра и target из чужого write-up требуют собственной проверки.
- **Следствие для будущих линейных моделей:** логистическая регрессия учится событию `target > 0`; обычная регрессия использует величину target или её преобразование. Выбор фиксируем после анализа положительных отсчётов, учитывая обе конкурсные метрики.

### Вопросы о пропусках

- **Обычные NaN:** готовой таблицы признаков пока нет; доли NaN для будущих признаков не рассчитаны.
- **`N` в ДНК:** неизвестный нуклеотид, требующий отдельного учёта. Посчитать доли на train/test whitelist и связь с train-target; не заполнять автоматически наиболее частой буквой.
- **Ноль в размеченном train:** отсутствие наблюдаемого сигнала в доступном эксперименте. Это отдельный случай от отсутствующей разметки.
- **Отсутствующие test-ответы:** у конкурсных видов скрыты намеренно; не заменять их нулями. У demo они доступны, но пока не загружены.
- **Границы последовательности:** контекст за пределами контига отсутствует. Будущие окна должны явно кодировать эту границу и не переходить в соседний контиг.
- **Проверка обработки:** на фиксированных validation-контигах сравнить согласованные варианты; статистики обработки вычислять на fit-части.

### Интерпретация ключей и дубликатов

- **Primary key:** `(assembly, contig, position, strand)` для pooled сигнала; при совместном хранении повторностей добавить `replicate` и тип трека.
- **Ожидаемая уникальность:** одна оценка на позицию и цепь внутри template конкретного набора.
- **Фактические дубликаты:** полный подсчёт ещё не выполнен. Нужно проверить пересечения whitelist-интервалов, повтор координат после раскрытия BED и соответствие template.
- **Причина допустимых повторов:** одна координата на разных цепях, в разных повторностях или треках — разные наблюдения. Одинаковые окна ДНК на разных координатах могут быть биологическими повторами, а не ошибкой файла.

## Время

- **Тренды и сезонность:** не применимо к индексам геномных позиций; координата не является временем.
- **Структурные сдвиги:** исследовать различия между контигами, видами и тканями. Для первого анализа используется одна сборка актинии со смешанными стадиями.
- **Изменения процесса сбора:** история лабораторного протокола и партий в текущем паспорте не установлена; отсутствие временного поля не доказывает отсутствие batch effects.
- **Запаздывание label:** прогноз временного события не ставится; target — уже измеренный экспериментальный сигнал.
- **Подходящая временная граница holdout:** временной split не выбран; основные кандидаты на разделение — целые контиги/хромосомы.

## Группы и зависимости

- Миллионы позиций принадлежат одним и тем же контигам; соседние окна перекрываются. Число позиций не равно числу независимых наблюдений.
- Обе цепи, повторности и все перекрывающиеся окна одного удерживаемого контига должны оставаться в одной части разбиения.
- Для Nematostella официальный train-whitelist содержит только 12 контигов. Число групп и их неодинаковый размер нужно учитывать при выборе локальной validation.
- Вид, ткань/стадия и экспериментальная повторность — возможные источники различий. Близость среднего GC train/test не исключает сдвиги по другим признакам.
- Бутстрэп отдельных соседних позиций может недооценивать неопределённость. Для будущих интервалов качества рассмотреть контиги или достаточно длинные блоки с явным описанием схемы.

## Пропуски, выбросы и аномалии

<!-- auto:eda-anomalies:start -->

> По доле нулей в train Nematostella следуют `Q1 = median = Q3 = 0`, поэтому IQR равен нулю; MAD также равен нулю. Обычное правило верхнего IQR-порога пометит любой положительный target как выброс. Для этой задачи это не основание удалять положительные позиции. Отдельно исследуем распределение `target > 0` и согласованность экстремумов между повторностями.

<!-- auto:eda-anomalies:end -->

| Проблема | Масштаб | Связь с target | Объяснение | Обработка |
|---|---:|---|---|---|
| Нулевая вариативность центральной части target | 99.9273% нулей по JSON | Положительные — полезный сигнал задачи | Сильный дисбаланс; IQR/MAD на полном target вырождаются | Не использовать их как автоматический фильтр |
| Очень большие readcounts | Масштаб пока неизвестен | Могут существенно влиять на регрессионную ошибку | Сильный биологический сигнал или технический эффект — требует проверки | Проверить повторности и контекст; преобразования обсуждать после измерения |
| N и неопределённые символы | Доли у актинии пока не подсчитаны | Связь с target не проверена | Неопределённость сборки и возможные особенности маппинга | Сохранить явный признак; не объявлять такие позиции гарантированными отрицательными |
| Пересекающиеся интервалы / повтор ключа | Полный аудит не проведён | Ошибка может изменить и target, и метрику | Возможное дублирование при парсинге | Проверить до создания выборки |

## Bias, покрытие и репрезентативность

- **Покрытие:** оцениваемый whitelist представляет отобранные участки генома; выводы не автоматически распространяются на исключённые повторы, короткие контиги и иные ткани.
- **Train/test GC:** у Nematostella 40.3286% против 40.2485%, разница −0.0801 процентного пункта. Это близость одного агрегата; полное отсутствие distribution shift не подтверждено.
- **Редкие события:** небольшая случайная выборка может содержать слишком мало положительных позиций для изучения закономерностей. Для исследовательских графиков указывать размер и способ отбора обеих групп.
- **Зависимость наблюдений:** позиции и цепи связаны общей последовательностью; оценки неопределённости должны учитывать группы.
- **Процесс измерения:** нулевые отсчёты могут отражать чувствительность эксперимента; сравнение повторностей ещё не проведено.
- **Обобщение:** закономерность на демонстрационной актинии не считается автоматически подтверждённой для пяти конкурсных видов.

## Рекомендации для model-ready выборки

Здесь фиксируются только обоснованные EDA-кандидаты. Реализация фильтров и preprocessing выполняется воспроизводимо в [[docs/04_features.md]] и внутри validation pipeline.

| Наблюдение | Затронутые строки / поля | Возможное действие | Как проверить | Решение |
|---|---|---|---|---|
| Для актинии более 311 млн train-значений | Все позиции и будущие признаки | Чтение частями, разреженные или компактные представления; обоснованная выборка fit | Рассчитать память и проверить на небольшом фрагменте | Требование к реализации; схема ещё не выбрана |
| Около 1375 отрицательных на одно положительное | Бинарное представление target | Рассмотреть sampling или веса только для обучения; evaluation сохранить естественным | Сравнить варианты на одном validation без изменения его распределения | Гипотеза для будущего baseline |
| Положительный target также содержит величину | Целевая переменная | Хранить исходный count и отдельно вычислять `count > 0` | Сверить обе версии на одних координатах | Требование к схеме данных |
| Наличие групп и перекрытий | Контиги, обе цепи, повторности | Разделять целыми контигами | Проверить непересечение списков и происхождение всех окон | Требование к Validation |
| Регистр и N могут нести информацию | Последовательность FASTA | Сохранить исходное состояние и исследовать отдельные признаки | Анализ связи с target по контигам; затем ablation на validation | Кандидат, полезность не подтверждена |
| Локальные мотивы ещё не исследованы | Производные признаки ДНК | Сравнить позиционное кодирование и k-меры разных длин | EDA по fit-данным, затем фиксированный модельный эксперимент | Кандидат; набор признаков не утверждён |

Оценка памяти: 100 плотных признаков `float32` на всех train-позициях актинии потребуют около **116.2 GiB** только под матрицу, без служебных объектов. Даже для линейной модели способ представления и объём fit-выборки должны быть явными. Это арифметическая оценка размера, а не замер потребления конкретной реализации.

```python
import json
from pathlib import Path

assemblies = json.loads(Path("data/raw/genome_metrics.json").read_text())["assemblies"]
for name, a in assemblies.items():
    n = a["template"]["train"]["length"]
    p = a["whitelist"]["nonzeros"]["train"]
    for split in ("train", "test"):
        assert a["template"][split]["length"] == 2 * a["whitelist"][split]["size_bp"]
    print(name, {
        "positions": n, "positive": p, "zero": n - p,
        "positive_pct": 100 * p / n,
        "constant_ap": p / n,
        "gc_train_pct": 100 * a["whitelist"]["train"]["gc_fraction"],
        "gc_test_pct": 100 * a["whitelist"]["test"]["gc_fraction"],
        "dense_100_float32_features_gib": n * 100 * 4 / 1024**3,
    })
```
